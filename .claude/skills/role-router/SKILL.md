# Mobile 项目角色路由

这是一个**薄路由 skill**，基于任务上下文决定是否接入角色。

## 何时使用

- 用户直接说"绘心""明策""码匠"
- 用户用角色缩写，如 `ui`、`pm`、`dev`
- 新的大功能开发（需要确认主导上下文）
- 任务涉及多个维度，需要先路由

## 路由步骤

1. **识别任务上下文**：
   - 是设计问题？→ 接入 `role-ui`
   - 是需求/业务问题？→ 接入 `role-pm`
   - 是开发实现？→ 接入 `role-dev`
   - 是架构设计？→ 接入 `role-arch`

2. **检查项目的 role-registry.md**：
   - `/Users/weiran/mobile/.claude/role-registry.md`

3. **决定角色接入层级**：
   - L0：不需要角色（简单改动、明确执行）
   - L1：参考角色摘要（需要某种判断口径）
   - L2：接入完整角色定义（复杂任务、多轮评审）

## 主导上下文判定

| 上下文 | 主导角色 | 示例任务 |
|------|--------|--------|
| 视觉/交互/样式 | `ui` | 页面重设计、响应式适配、交互改进 |
| 需求/业务/流程 | `pm` | 功能规划、优先级确认、用户流程 |
| 开发/实现/调试 | `dev` | 写代码、修 bug、性能优化 |
| 架构/边界/选型 | `arch` | 页面结构、导航设计、技术方案 |
| 简单执行 | 无角色 | typo、配置、小样式调整 |

## Mobile 项目特点

- 所有页面使用 **Vue 3 + CDN**（不是 SFC）
- 绿色主题设计：`#5dd4cc`
- 响应式移动优先
- 页面间有导航关系

## 快速检查清单

- [ ] 任务是否涉及页面视觉？→ 可能需要 `ui`
- [ ] 是否改变了用户流程？→ 可能需要 `pm`
- [ ] 是否涉及多文件改动？→ 可能需要 `dev`
- [ ] 是否影响页面架构？→ 可能需要 `arch`
- [ ] 是否只是样式/文案调整？→ 可能不需要角色
