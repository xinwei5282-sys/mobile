## 一、项目概述

### 1.1 需求背景

当前试用营邀请系统支持 KOC 个人邀请推广。为了帮助部分 KOC 扩大推广范围，允许 KOC 招募推广员（下属），每个下属获得独立的邀请码。用户通过下属的邀请码加入试用营后，奖励全部计入该 KOC 的账户。形成 **KOC → 下属推广员 → 用户** 的三层邀请体系，实现裂变式增长。

### 1.2 核心目标

- **扩大推广覆盖** — 通过下属推广员触及更多潜在用户
- **实现裂变增长** — 激励KOC主动招募推广员
- **数据追踪清晰** — 完整记录邀请链路：KOC → 下属 → 用户
- **简化管理流程** — 下属无需注册账户，拿码即可推广

### 1.3 关键特性

- ✅ 下属只是推广员身份，**不需要在平台注册账户**
- ✅ 一个下属对应一个邀请码（1:1 关系）
- ✅ 邀请奖励全部计入 KOC 名下（下属奖励由 KOC 线下分配）
- ✅ 邀请链路完整追踪（KOC → 下属 → 用户）
- ✅ **用户标签自动打标** — KOC 创建下属时设置标签，用户通过邀请码加入时自动打上该标签，便于 KOC 业务管理和用户分类

### 1.4 适用范围

- **移动端**：KOC 团队管理功能（查看、添加、删除下属，查看邀请明细）
- **后端 API**：团队管理、邀请统计、邀请追踪
- **PC 管理后台**：暂不在本期范围内（后续迭代）

## 二、用户故事

### Story 1：KOC 添加推广员
**作为** 有团队管理权限的 KOC  
**我想要** 招募推广员加入我的团队，并为推广员的用户打上标签便于管理  
**以便于** 扩大邀请覆盖范围，精准追踪用户来源

**场景**：
1. KOC 进入"团队管理" tab
2. 点击"+ 添加下属"
3. 输入下属的名字、电话和标签（标签由 KOC 自定义，如"微信群1"、"朋友圈"、"线下活动"等）
4. 点击"生成邀请码"
5. 系统返回邀请码（如 `KOC_M_001234`）和绑定的标签
6. KOC 复制邀请码或分享给下属
7. 下属拿到码后直接推广（无需注册）
8. 用户通过该邀请码添加鱼丸时，系统自动给用户打上对应的标签（标签来自该邀请码的绑定标签）

### Story 2：KOC 查看团队邀请成果
**作为** KOC  
**我想要** 看到每个下属通过邀请码带来的用户和成果，按标签分类管理  
**以便于** 评估推广效果、调整策略、进行精准运营

**场景**：
1. 进入"团队管理" tab
2. 看到团队统计（总下属数、总邀请数、总转化数）
3. 看到下属列表，每个下属的邀请数、转化数、绑定的标签
4. 点击某个下属的"查看详情"看该下属邀请来的用户列表
5. 支持按状态筛选（推荐成功、已领卡、已入营、未入营）
6. KOC 可在管理后台或分析页面按标签筛选、统计、导出用户数据

### Story 3：KOC 删除下属
**作为** KOC  
**我想要** 删除不再合作的下属  
**以便于** 管理团队

**场景**：
1. 在"团队管理"中找到要删除的下属
2. 点击"删除"按钮
3. 确认删除
4. 下属状态变为"已删除"，邀请码失效，不能生成新邀请
5. **下属原有的邀请记录保留在 KOC 名义下**（所有奖励仍属于 KOC）

     - 加入时间（该下属添加的时间）

     - [查看邀请码] → 弹出邀请码（支持复制）
     - [查看详情] → 跳转查看该下属的邀请明细
     - [删除] → 删除下属（确认对话框）

**交互流程**：
1. 输入框1：下属名字（必填，长度1-50）
2. 输入框2：下属电话（必填，正则校验）
3. 输入框3：标签（必填，自由文本，长度1-30，如"微信群1"、"朋友圈"、"线下活动"）

5. 后端返回邀请码和绑定的标签
6. 弹窗显示：
   - 邀请码（大字体展示，便于识别）
   - 标签（展示该邀请码绑定的标签）
   - [复制邀请码] 按钮（点击后提示"已复制"）
   - [分享邀请码] 按钮（调用系统分享）
   - 提示文案："请将邀请码发送给下属，下属拿到码后即可开始推广。用户通过该邀请码加入时，自动打上 '{标签}' 标签"

**特殊说明**：
- 一个下属一个邀请码，邀请码是唯一的
- 一个下属一个标签，标签由 KOC 自定义
- 邀请码和标签生成后立即返回，无需等待激活流程
- 标签不能为空，必须设置

#### 3.1.3 下属邀请明细页面
**展示内容**：
- 下属的名字和邀请码信息
- 邀请统计（按状态分类）：
  - 推荐成功：X 人
  - 已领卡：X 人
  - 已入营：X 人
  - 未入营：X 人
- 邀请用户列表（可筛选、分页）
  - 用户头像、微信昵称、加入时间、当前状态

**筛选功能**：
- 状态筛选：全部、推荐成功、已领卡、已入营、未入营
- 时间排序：按加入时间倒序

## 五、数据模型

### 5.1 新建表：`koc_team_member`

```sql
CREATE TABLE koc_team_member (
  id                    BIGINT PRIMARY KEY AUTO_INCREMENT,
  koc_union_user_id     BIGINT NOT NULL COMMENT 'KOC的union_user_id',
  distributor_name      VARCHAR(100) NOT NULL COMMENT '下属名字',
  distributor_phone     VARCHAR(20) COMMENT '下属电话',
  invite_code           VARCHAR(50) NOT NULL UNIQUE COMMENT '邀请码（全局唯一）',
  invite_code_created_at DATETIME NOT NULL COMMENT '邀请码生成时间',
  tag                   VARCHAR(50) NOT NULL COMMENT '标签（KOC自定义，用于用户分类管理）',
  status                INT NOT NULL DEFAULT 1 COMMENT '1-激活 2-已删除',
  gmt_create            DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  gmt_update            DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  gmt_delete            DATETIME COMMENT '软删除时间',
  
  INDEX idx_koc_id (koc_union_user_id),
  INDEX idx_invite_code (invite_code),
  INDEX idx_tag (tag),
  INDEX idx_status (status)
);
```

### 5.2 修改表：`work_user_channel_try`

**新增字段**（用于追踪邀请来源和标签）：
```sql
ALTER TABLE work_user_channel_try ADD COLUMN (
  source_distributor_invite_code VARCHAR(50) COMMENT '下属的邀请码',
  source_distributor_id          BIGINT COMMENT 'koc_team_member表的id',
  source_distributor_tag         VARCHAR(50) COMMENT '用户被打上的标签（来自邀请码的绑定标签）',
  
  INDEX idx_source_code (source_distributor_invite_code),
  INDEX idx_source_tag (source_distributor_tag)
);
```

**说明**：
- `source_distributor_invite_code` 为 NULL 表示由 KOC 直接邀请
- 非 NULL 表示由该邀请码对应的下属邀请
- `source_distributor_tag` 存储用户被打上的标签，便于后续按标签筛选和分析

### 5.3 用户标签打标流程（核心改造）

**流程**：
1. 用户在试用营页面输入或扫描下属的邀请码
2. 后端接收邀请码，查询 `koc_team_member` 表找到对应的标签
3. 用户完成领鱼丸操作
4. **后端调用企微 API**，自动给用户打上对应的标签
5. 打标签结果记录在 `work_user_channel_try.source_distributor_tag`
6. 如果打标签失败，触发重试机制（最多重试 3 次，间隔 5 分钟）
7. 所有操作记录日志，便于后续排查

**关键点**：
- 标签打标是**异步操作**，不阻塞用户领鱼丸流程
- 即使打标签失败，邀请记录仍然生成，用户仍然完成领鱼丸
- 需要监控打标签的成功率和失败原因
- 提供管理后台接口，能手动重新打标签

**企微 API**：
- 需要调用企微的标签创建和赋值 API
- 标签名称格式：统一使用 KOC 设置的标签文本（如"微信群1"）
- 如果标签不存在，先创建再赋值

---

### 5.4 邀请码生成规则

**格式**：`KOC_M_{随机或序列号}`

**要求**：
- 长度：16-20 字符
- 字符集：大写字母 + 数字
- 唯一性：全局唯一（数据库 UNIQUE 约束）
- 可识别性：能快速判断是下属邀请码（前缀 `KOC_M_`）

**算法建议**：
- 使用随机算法（UUID 截断或纯随机数字）
- 在生成邀请码时检查唯一性，冲突则重新生成

## 六、API 接口清单

### 6.1 KOC 团队管理 API

#### 6.1.1 添加下属（生成邀请码）
```
POST /try/koc/team/add-member
Content-Type: application/json

Request: {
  distributorName: "张三",
  distributorPhone: "13812345678",
  tag: "微信群1"
}

Response: {
  code: 200,
  data: {
    distributorId: 123456,
    distributorName: "张三",
    inviteCode: "KOC_M_001234",
    tag: "微信群1",
    inviteCodeCreatedAt: "2026-05-07 10:30:00"
  },
  message: "邀请码生成成功"
}
```

**说明**：
- 邀请码生成后立即返回，无需额外激活步骤
- 邀请码是全局唯一的
- `tag` 是必填参数，由 KOC 自定义，长度 1-50 字符
- 用户通过该邀请码添加鱼丸时，系统会自动给用户打上对应的标签

#### 6.1.2 获取团队成员列表
```
GET /try/koc/team/members?pageIndex=1&pageSize=10

Response: {
  code: 200,
  data: {
    items: [
      {
        distributorId: 123456,
        distributorName: "张三",
        distributorPhone: "13812345678",
        inviteCode: "KOC_M_001234",
        tag: "微信群1",
        joinTime: "2026-05-01 10:30:00",
        status: 1,
        inviteCount: 28,
        convertCount: 10,
        tryCount: 20,
        chatCount: 8
      }
    ],
    pageIndex: 1,
    pageSize: 10,
    total: 5,
    summary: {
      totalMembers: 5,
      totalInviteCount: 128,
      totalConvertCount: 42
    }
  }
}
```

**字段说明**：
- `tag`: 该下属对应的标签
- `inviteCount`: 该下属邀请的总人数
- `convertCount`: 已入营的人数（已支付的用户）
- `tryCount`: 已领卡的人数
- `chatCount`: 已入营的人数（等同 convertCount）

```
DELETE /try/koc/team/member/{distributorId}

Response: {
  code: 200,

**说明**：
- 删除后，该下属的邀请码失效

## 七、交互流程

### 7.1 KOC 添加下属流程图

```

    ↓

    ↓

### 7.2 用户通过下属邀请码加入试用营流程

```
下属拿到邀请码 (KOC_M_001234)
    ↓

    ↓
用户扫码 / 点击链接 → 进入试用营
    ↓
用户输入邀请码或链接中包含邀请码
    ↓

    ↓
后端记录：
  - user_id
  - source_distributor_invite_code = "KOC_M_001234"
  - source_distributor_id = 该邀请码对应的 koc_team_member.id
    ↓
KOC 在"团队管理"页看到该邀请成果
下属的邀请数、转化数都会增加
```
